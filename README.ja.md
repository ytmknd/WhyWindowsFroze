# WhyWindowsFroze

Windows PC のフリーズの原因を、**既存のイベントログ**とシステムの状態から診断する GUI ツールです。

[English README](README.md)

- .NET 10 ランタイムを同梱した自己完結型の単一 exe（約 47MB、Windows 10/11 x64）。インストール不要、常駐なし、システム設定の変更なし
- 管理者として実行（起動時に UAC で昇格。Security ログ、Prefetch、フィルタードライバー、ディスクの信頼性情報の読み取りに必要）
- 画面・所見・レポートは、Windows の表示言語が日本語なら日本語、それ以外なら英語で表示します。イベントのメッセージ本文は Windows が記録したもので、OS の言語のままです。

## ビルド

```
dotnet publish -c Release -o publish
```
→ `publish\WhyWindowsFroze.exe`（この 1 ファイルだけを配布すれば動きます）。ARM64 向けは `-r win-arm64` を付けて発行してください。

## 検出するフリーズ

| 種類 | 検出方法 |
|---|---|
| 強制電源断（電源ボタン） | Kernel-Power 41（BugCheck なし、OS が電源ボタンの押下を記録） |
| 予期しない電源断/リセット | Kernel-Power 41（BugCheck なし、電源ボタンの記録なし。電源ボタン、停電、電源ユニット/AC アダプター、ハードウェアリセットなどを区別できない） |
| ブルースクリーン | Kernel-Power 41 / BugCheck 1001（BugCheck コードあり） |
| 画面/システムの一時停止（回復） | 画面やシステム全体の停止を示すイベントを、5 分以内のまとまりで 1 件として扱う: TDR 4101、ライブカーネルイベント、DWM の異常終了/応答停止、コミット枯渇 (2004)、カーネルプール枯渇（新しい 30 件まで） |
| アプリ応答停止・I/O 遅延 | アプリ/Explorer の応答停止 (1002)、ディスク I/O の再試行/リセット、書き込み遅延、Winlogon 通知の遅延だけのまとまり。PC 全体が止まったとは限らないため別枠で表示（新しい 30 件まで） |
| 指定時刻 | ［発生時刻を指定］または `/at:` で利用者が指定した時刻（ログに何も残らなかったフリーズにも使える） |

一覧とレポートでは「Windows 全体の停止」と「アプリ単体の応答停止・I/O 遅延」を分けて表示します。

## 原因の診断

インシデントごとに、次の根拠を原因カテゴリ別に点数化します。根拠には **[発生前]**（基準時刻より前）、**[起点]**（停止を示したイベント自身）、**[発生後]**（結果として起きた可能性がある）、**[現在の状態]**（解析時点の健全性）の区別を付けます。**確信度**（高/中/低）は [発生前] の根拠と発生時の状況（BugCheck、復帰/起動/ログオン直後など）だけから判定し、確信度、点数の順に並べます。基準時刻は、電源断では最後の記録、回復型では最初の起点イベント、指定時刻ではその時刻です。

- **BugCheck コード**: 約 50 種類について名前・意味・カテゴリを表示（例: 0x9F → 電源、0x116/0x117 → GPU、0x7A/0xF4 → ストレージ、0x124 → ハードウェア、0x133 → ドライバー）
- **基準時刻の直前（既定 30 分）の既知イベント**: 基準時刻の前 5 分以内のイベントは 2 倍で数える。基準時刻より後のイベントは 1 点、起点イベントは種類ごとに 1 回だけ数える。頻発するノイズに引きずられないよう、同じ種類のイベントは 3 件まで数える
- **発生のパターン**: スリープ復帰の直後、OS 起動の直後、ログオンの直後
- **直前 3 日以内の更新/インストール**: Windows Update、ドライバー、サービス、MSI
- **直前に起動したアプリ** (Prefetch)
- **現在の健全性の問題**（下記）

| カテゴリ | 主な根拠 |
|---|---|
| GPU / 画面表示 | TDR 4101、LiveKernelEvent 141/117/193、DWM の停止/クラッシュ、nvlddmkm/amdkmdag/igfx のエラー、DxgKrnl |
| ストレージ | disk 7/11/51/52/153/154/157、storahci/stornvme 129、NTFS、書き込み遅延、Storport、空き容量不足、SSD の消耗/訂正不能エラー |
| メモリ / リソース枯渇 | 2004 コミット枯渇、Srv 2019/2020 プール枯渇、Resource-Exhaustion、物理メモリ不足、ページファイルなし |
| ハードウェア / 温度 | WHEA、メモリ診断のエラー、CPU の速度制限、温度警告、古い BIOS |
| 電源 / スリープ | SleepInProgress、BugCheck 9F/A0/14F/15F/1A8、LiveKernelEvent 1a8 等、復帰直後の停止 |
| アプリケーション | アプリの応答停止/クラッシュ（Office/Teams は重く数える）、Office の警告ダイアログ、DCOM タイムアウト |
| シェル / ログオン | Explorer/スタート/検索/IME の応答停止、LiveKernelEvent 1a1、Winlogon 6005/6006/4005、プロファイルの問題、ログオン直後の停止 |
| 認証 | Entra ID / WAM (AAD) のエラー |
| ネットワーク | NIC のリセット (NDIS)、NIC/無線 LAN ドライバーのエラー、SMB 接続の問題、TCP ポート枯渇 |
| セキュリティ製品 | Defender の検出、コード整合性ブロック、フィルターの読み込み失敗、ウイルス対策の二重稼働、他社製フィルタードライバー |
| 更新 / インストール | Windows Update、ドライバーのインストール、新しいサービス、MSI、再起動待ち |
| ドライバー / OS | その他の BugCheck、サービスの異常終了/タイムアウト、重要プロセスの終了、問題のあるデバイス、起動直後の停止 |

複数のフリーズに共通する原因カテゴリ、発生パターン（復帰直後、起動直後、ログオン直後、時間帯の集中）、ユーザーの偏りは「推奨事項」にまとめます。

## 健全性チェック（現在の状態）

システムドライブの空き容量、ディスクの健康状態と SSD の消耗度/温度/訂正不能エラー、物理メモリ量とコミット使用率、ページファイル、連続稼働時間、問題のあるデバイス、GPU ドライバーと BIOS の古さ、Basic Display Adapter での動作、ウイルス対策の二重稼働、他社製のファイルシステムフィルター、再起動待ちの更新、メモリダンプの設定。

## 使い方

1. 対象 PC で `WhyWindowsFroze.exe` を起動し、［解析開始］を押す
2. 上の一覧にフリーズが新しい順に並ぶ。行を選ぶと下のタブに詳細が出る
   - **原因と所見** / **タイムライン**（重要度で色分け、絞り込み、全文表示）/ **健全性チェック** / **期間内の既知イベント** / **アプリ実行履歴** / **ダンプ / WER** / **ユーザー設定** / **システム情報** / **推奨事項** / **調査範囲**（ログごとの取得成否・ログなし、取得件数、上限到達の有無）
3. ［HTML レポートを開く］／［出力フォルダーを開く］で、保存された結果を確認する（ZIP を調査担当者に渡せます）

一覧の行は Ctrl+C でコピーできます。ショートカット用の引数: `/auto`（起動直後に解析開始）、`/days:N`（期間、既定 30 日）、`/window:N`（時間窓、既定 30 分）、`/at:"yyyy-MM-dd HH:mm"`（フリーズの発生時刻）、`/lang:ja` または `/lang:en`（表示言語の指定）

## 出力

`WhyWindowsFroze_<PC名>_<日時>\`（と同名の .zip）: `report.html`、`summary.txt`、`incidentNN_events.csv`、`evtx\`（関連ログの生データ）、`wer\`（WER レポート）

## 制約・注意

- 強制電源断ではダンプが残らず、フリーズ中のことはイベントログに残らないことが多いです。手がかりがない場合は「手がかりなし」と表示します。
- 原因カテゴリは、イベントの組み合わせから推定した候補です。確定には、ダンプの解析や切り分け（ドライバー更新、クリーンブートなど）が必要です。
- 健全性チェックの結果は解析した時点の状態で、フリーズ当時の状態ではありません。
- 回復型は種類ごとに新しい 30 件だけを詳しく解析します。候補の総数は「調査範囲」に表示します。アプリの応答停止は、ユーザーが固まったアプリを閉じたときにも記録されます。
- 検索には上限があります（期間全体は 1 回の検索につき 10,000 件、時間窓はログごとに 5,000 件）。時間窓は新しい順に読むため、上限に達しても停止直前の記録は残ります。読めなかったログと上限に達した検索は「調査範囲」に載るので、「検出なし」と「調べられなかった」を区別できます。
- 再起動せずに回復し、ログに何も残らなかったフリーズは自動では検出できません。［発生時刻を指定］を使ってください。
- ユーザー別のレジストリ設定は、そのユーザーがログオン中の場合だけ取得できます。
- 出力にはユーザー名、アプリのコマンドライン、ファイルの URL が含まれることがあります。取り扱いに注意してください。
